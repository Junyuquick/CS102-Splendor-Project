Validation Story
----------------

MoveValidator
  1. reject null moves
  2. identify the concrete move subtype
  3. hand the move to the matching rule class
  4. return null when valid, otherwise a readable error message

TakeDifferentMoveRule
  1. check the token-selection shape
  2. check bank availability
  3. enforce fallback / reduced-take rules when the bank is constrained
  4. enforce token-cap rules

TakeSameMoveRule
  1. require exactly one chosen color
  2. require the configured same-color count
  3. enforce bank-supply and minimum-remaining rules
  4. enforce token-cap rules

BuyMoveRule
  1. require a target card
  2. verify the card source (face-up or reserved)
  3. verify free-card payment shape
  4. verify affordability via PaymentCalculator
  5. verify exact submitted payment tokens

AvailableMovesInspector
  builds probe moves and asks existing rule classes whether reserve, buy,
  or return-token alternatives are available
