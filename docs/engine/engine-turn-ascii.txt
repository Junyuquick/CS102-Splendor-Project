Detailed Turn Story
-------------------

TurnResolutionService
  1. validate the move
  2. execute the move
  3. enforce token-limit cleanup if needed
  4. assign the best available nobles
  5. advance the turn and check endgame state
  6. package everything into TurnResolutionResult

Per-Class Notes
---------------

MoveExecutor.java
  applies already-validated move effects to GameState
  depends on -> Move subclasses, Board, GemBank, Player, Config
  internal flow -> execute() dispatches to applyTokenTake(),
                   applyReserve(), applyBuy(), applyTokenReturn()

NobleAssigner.java
  finds eligible nobles and can assign a chosen one
  depends on -> Board, GameState, Player, NobleTile

TurnAdvanceResult.java
  small value object returned by turn progression

TurnManager.java
  controls current-player index and final-round marker
  depends on -> GameState

TurnPostProcessor.java
  handles token-limit cleanup and noble assignment
  depends on -> Config, NobleAssigner, GameState, Player

TurnProgressionService.java
  triggers final round, advances turn, and determines a winner if the
  final round has completed
  depends on -> WinnerChecker, TurnManager, GameState

TurnResolutionResult.java
  full outcome container for one resolved move

TurnResolutionService.java
  orchestrates validator + executor + post-processor + progression
  depends on -> MoveValidator, MoveExecutor, TurnPostProcessor,
                WinnerChecker, TurnManager, TurnProgressionService

WinnerChecker.java
  decides final-round trigger and winner selection
  depends on -> Config, GameState, Player
