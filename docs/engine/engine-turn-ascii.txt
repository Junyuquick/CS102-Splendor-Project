Detailed Turn Story
-------------------

TurnResolutionService
  1. validate the move
  2. execute the move
  3. discard extra tokens if needed
  4. assign nobles if eligible
  5. advance the turn and check for endgame
  6. package everything into TurnResolutionResult

Per-Class Notes
---------------

MoveExecutor.java
  applies legal move effects to GameState
  depends on -> Move subclasses, Board, GemBank, Player, Config
  simplified flow -> execute() dispatches, helpers handle small steps like
                     reserve gold, payment collection, and market refill

NobleAssigner.java
  finds eligible nobles and assigns them
  depends on -> Board, GameState, Player, NobleTile

TurnAdvanceResult.java
  small immutable-like result for turn progression

TurnManager.java
  controls current player index and final-round marker
  depends on -> GameState

TurnPostProcessor.java
  handles post-move token limit and noble assignment
  depends on -> Config, NobleAssigner, GameState, Player
  simplified flow -> enforceTokenLimit() now loops through discardOneRound()
                     and noble assignment uses small comparison helpers

TurnProgressionService.java
  triggers final round, advances turn, decides whether winner exists
  depends on -> WinnerChecker, TurnManager, GameState
  simplified flow -> triggerFinalRoundIfNeeded() -> advanceTurn()
                     -> determineWinnerIfGameEnded()

TurnResolutionResult.java
  full outcome container for one resolved move

TurnResolutionService.java
  orchestrates validator + executor + post-processor + progression
  depends on -> MoveValidator, MoveExecutor, TurnPostProcessor,
                WinnerChecker, TurnManager, TurnProgressionService
  simplified flow -> executeMove(), discardExtraTokens(), assignNobles(),
                     advanceTurn(), buildSuccessResult()

WinnerChecker.java
  decides final-round trigger and winner selection
  depends on -> Config, GameState, Player
